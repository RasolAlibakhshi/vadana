## ✨ از کارهای تکراری، یک سناریو بسازید

**Vadana Automator** ابزاری دسکتاپ بر پایه Electron و Playwright است که فرآیندهای تکراری در سامانه «نقشه‌وادانا» دانشگاه آزاد اسلامی را ساده‌تر می‌کند. تعاملات خود را در مرورگر ضبط کنید، کد تولیدشده را به برنامه بدهید و زمان اجرای آن را مشخص کنید.

برای شروع سناریوهای ساده نیازی به نوشتن کد از صفر ندارید؛ کاربران باتجربه نیز می‌توانند مراحل ضبط‌شده را متناسب با نیاز خود اصلاح کنند.

| قابلیت | کاربرد |
| :--- | :--- |
| 🎬 **ضبط تعاملات** | تولید کد از کلیک‌ها، تایپ‌ها و انتخاب‌ها با Playwright Codegen |
| 🧹 **آماده‌سازی خودکار کد** | پاک‌سازی برخی کاراکترهای خاص، استخراج بدنه تست و بازنویسی برخی locatorهای لینک |
| 🗓️ **زمان‌بندی اجرا** | انتخاب تاریخ و ساعت محلی برای اجرای یک‌باره هر وظیفه |
| 🐢 **کنترل سرعت** | تنظیم مکث میان عملیات مرورگر با SlowMo |
| 👀 **فرصت بررسی نتیجه** | باز نگه داشتن مرورگر پس از اجرای سناریو با Close Delay |
| ▶️ **اجرای آزمایشی** | اجرای فوری وظیفه ثبت‌شده با دکمه «تست الان» |
| 📋 **گزارش اجرا** | نمایش زنده پیام‌های اجرا و ذخیره فایل لاگ و نتیجه |
| 🛡️ **جلوگیری از اجرای هم‌زمان یک وظیفه** | مسدود کردن اجرای دوباره همان وظیفه تا پایان اجرای جاری |

## 🚀 شروع سریع

در پوشه اصلی پروژه، این سه دستور را به‌ترتیب اجرا کنید:

```bash
npm install
npx playwright install chromium
npm run dev
```

**پیش‌نیازها:** Node.js و npm سازگار با نسخه وابستگی‌های پروژه، دسترسی اینترنت برای نصب بسته‌ها و مرورگر، و دسترسی به سامانه وادانا. نسخه Node.js را با نیازمندی‌های نسخه نصب‌شده Electron و Playwright تطبیق دهید؛ در `package.json` حداقل نسخه مشخص نشده است.

| مرحله | نتیجه |
| :--- | :--- |
| `npm install` | نصب وابستگی‌های پروژه |
| `npx playwright install chromium` | دریافت مرورگر مورد استفاده Playwright |
| `npm run dev` | باز شدن رابط دسکتاپ برنامه |

> **دستور اجرای این مخزن `npm run dev` است.** در نسخه فعلی، اسکریپت `start` در `package.json` تعریف نشده است.

## 🎬 ضبط سناریو در وادانا

در یک ترمینال دیگر و در پوشه پروژه اجرا کنید:

```bash
npx playwright codegen https://vadamap.ec.iau.ir
```

1. در مرورگر بازشده، وارد سامانه شوید و مراحل مورد نظر را انجام دهید.
2. کد تعاملات ثبت‌شده را در پنجره **Playwright Inspector** بررسی کنید.
3. برای سازگاری با مبدل فعلی، خروجی **Playwright Test / JavaScript** را انتخاب کنید.
4. پس از پایان ضبط، کد را با دکمه **Copy** کپی کنید.
5. کد را در فرم ثبت وظیفه برنامه قرار دهید.

> **بهترین نقطه شروع:** یک سناریوی کوتاه ضبط کنید و پیش از سپردن آن به زمان‌بندی، یک بار اجرای آزمایشی انجام دهید.

مبدل هنگام ثبت وظیفه، بخشی از آماده‌سازی کد را انجام می‌دهد. با این حال، تغییر ساختار سایت، متن لینک‌ها یا سناریوهای پیچیده ممکن است به اصلاح دستی نیاز داشته باشد. این تبدیل، صحت تمام خروجی‌های Codegen یا پایداری همه انتخابگرها را تضمین نمی‌کند.

## 🕹️ از ثبت وظیفه تا مشاهده نتیجه

### ۱. مشخصات اجرا را تنظیم کنید

| فیلد | توضیح | نمونه |
| :--- | :--- | :--- |
| **عنوان وظیفه** | نام قابل تشخیص برای سناریو | «بررسی صفحه درس» |
| **تاریخ و ساعت اجرا** | یک زمان آینده بر اساس ساعت محلی سیستم | زمان دلخواه از انتخابگر تاریخ و ساعت |
| **SlowMo** | مکث میان عملیات مرورگر، بر حسب میلی‌ثانیه | `800` |
| **Close Delay** | مدت باز ماندن مرورگر پس از پایان عملیات، بر حسب ثانیه | `15` |
| **کد Playwright** | کد JavaScript ضبط‌شده | خروجی Inspector |

**SlowMo** مشاهده مراحل را آسان‌تر می‌کند؛ افزایش آن به‌تنهایی تضمینی برای رفع خطاهای سایت یا انتخابگرها نیست. **Close Delay** فرصت بررسی صفحه نهایی را فراهم می‌کند و پس از خطای اجرا نیز اعمال می‌شود.

### ۲. وظیفه را ثبت و آزمایش کنید

پس از تکمیل فرم، روی دکمه ثبت کلیک کنید. وظیفه در فهرست قرار می‌گیرد و برای زمان انتخاب‌شده آماده می‌شود. برای اجرای فوری، دکمه **«تست الان»** همان وظیفه را بزنید و پیام‌های اجرا را در بخش لاگ دنبال کنید.

اجرای آزمایشی، زمان‌بندی اصلی را لغو نمی‌کند. دکمه **«حذف»** وظیفه ذخیره‌شده و زمان‌بندی آن را حذف می‌کند؛ اجرای در حال انجام را متوقف نمی‌کند.

### ۳. برنامه را برای اجرای زمان‌بندی‌شده باز نگه دارید

زمان‌بندی داخل خود برنامه انجام می‌شود؛ در زمان اجرا، برنامه باید فعال و سیستم روشن و بیدار باشد. با باز شدن دوباره برنامه، وظایفی که زمانشان هنوز نرسیده است دوباره زمان‌بندی می‌شوند. وظایفی که موعدشان گذشته است، هنگام شروع برنامه به‌صورت خودکار اجرا نمی‌شوند.

هر اجرا با یک مرورگر و context تازه آغاز می‌شود؛ نشست ورود اجرای قبلی به‌صورت خودکار منتقل نمی‌شود. مراحل لازم برای ورود را در سناریوی خود در نظر بگیرید.

## 🧩 پشت صحنه برنامه

جریان کار از ثبت سناریو تا اجرای مرورگر:

```text
Codegen → Task Form → IPC → Code Transformer → Saved Script
                                                    ↓
Live Logs ← Renderer ← Main Process ← Scheduler → Chromium
```

رابط کاربری و فرآیند اصلی از هم جدا هستند. رابط، اطلاعات وظیفه را از طریق پل preload و IPC ارسال می‌کند؛ فرآیند اصلی مسئول ذخیره‌سازی، زمان‌بندی و اجرای مرورگر است.

```text
vadana_hozor/
├── package.json                 # وابستگی‌ها و دستور اجرای برنامه
├── README.md                    # راهنمای پروژه
└── src/
    ├── main.js                  # مدیریت وظایف، زمان‌بندی و مرورگر
    ├── preload.js               # پل ارتباطی رابط و فرآیند اصلی
    ├── renderer/
    │   ├── index.html           # رابط کاربری
    │   └── ui.js                # فرم، فهرست وظایف و لاگ زنده
    └── utils/
        └── codeTransformer.js   # تبدیل کد ضبط‌شده به تابع اجرایی
```

| بخش | مسئولیت |
| :--- | :--- |
| `src/main.js` | راه‌اندازی Electron، مدیریت IPC، ذخیره وظایف، اجرای Chromium و ذخیره نتایج |
| `src/utils/codeTransformer.js` | پردازش خروجی Codegen و ساخت تابع `module.exports` |
| `src/preload.js` | در اختیار گذاشتن API ارتباطی برای رابط کاربری |
| `src/renderer/ui.js` | ثبت و حذف وظیفه، اجرای فوری، نمایش فهرست و دریافت لاگ |

زمان‌بندی فعلی با **`setTimeout`** انجام می‌شود و فاصله‌های طولانی در چند مرحله مدیریت می‌شوند. بسته `node-cron` در وابستگی‌ها وجود دارد، اما زمان‌بند فعلی از آن استفاده نمی‌کند.

### 🧹 مبدل کد دقیقاً چه می‌کند؟

1. برخی بازه‌های یونیکد، از جمله کاراکترهای ناحیه خصوصی و نویسه‌های نامرئی مشخص را با فاصله جایگزین می‌کند.
2. الگوهای مشخصی از خطوط import و require مربوط به تست را حذف می‌کند.
3. در صورت تطبیق ساختار، بدنه `test(...)` را استخراج می‌کند.
4. برخی فراخوانی‌های `getByRole('link', ...)` را به جست‌وجوی لینک بر اساس بخشی از متن تبدیل می‌کند.
5. کد را داخل تابعی با دسترسی به `page`، `context`، `browser` و `log` قرار می‌دهد و زمان انتظار پیش‌فرض صفحه را روی **۱۰ ثانیه** تنظیم می‌کند.

این پردازش مبتنی بر Regex است؛ برای مثال، تبدیل انتخابگر لینک به `.first()` ممکن است اولین مورد از چند نتیجه مشابه را انتخاب کند. سناریوهای دارای assertion یا ساختارهای خارج از الگوی پشتیبانی‌شده ممکن است نیاز به تغییر داشته باشند. پاک‌سازی متن نیز به معنای اعتبارسنجی کامل یا ایمن‌سازی کد اجرایی نیست.

## 📂 وظایف و گزارش‌ها کجا ذخیره می‌شوند؟

داده‌های فعال برنامه در پوشه `data` زیر مسیر **`app.getPath('userData')`** ذخیره می‌شوند؛ محل آن به سیستم‌عامل و تنظیمات Electron بستگی دارد. فایل `data/jobs.json` داخل مخزن، محل ذخیره‌سازی فعال این پیاده‌سازی نیست.

```text
<userData>/data/
├── jobs.json                    # مشخصات وظایف
├── scripts/
│   └── <jobId>.js               # کد تبدیل‌شده هر وظیفه
└── runs/
    └── <runId>/
        ├── run.log              # پیام‌های اجرای همان نوبت
        └── result.json          # نتیجه و مشخصات اجرای همان نوبت
```
